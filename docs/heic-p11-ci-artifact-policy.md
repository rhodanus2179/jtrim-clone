# HEIC distribution-safe CI behavior

2026-10-20: a legacy P2 \`heic-wasm-validation.yml\` workflow still
included an \`actions/upload-artifact@v4\` step with one-day retention
for the **old, unapproved libheif-js 1.23.5 WASM bundle**.

This was inconsistent with the project release HOLD policy, even though it
was not committed to \`main\` or deployed to GitHub Pages. We removed that
step in P11. All HEIC test workflows now use short-lived runner-local files
and write only ordinary build/test logs. The CI smoke test rejects a future
reintroduction of \`upload-artifact\` and \`gh release create/upload\` in HEIC
test workflows.

**History:** artifacts generated by earlier runs may remain accessible until
their one-day retention expires. Updating the workflow prevents future
artifacts but does not retroactively delete already-stored artifacts.
Administrative deletion through GitHub Actions UI/API may be appropriate.

Neither current test success nor removing an artifact constitutes an LGPL-3.0
or HEVC patent-license authorization. The production release gate stays HOLD.
